# SC_AI 로드맵 (2026-10-02 기준)

목표: **Pluto를 이기는 브루드워 봇.** Pluto(tscmoo, CoG 2026 우승, 3.15억 파라미터 자기대전 RL, 바이너리만 공개)를
이기면 봇 세계 1위다. 지금 구조(McRave 몸체 + LLM 실시간 레버)로는 McRave 자체도 못 넘으므로(아래 "지금까지
배운 것"), 학습 요소가 반드시 들어가야 한다. 단계마다 **통과 기준**을 두고, 못 넘으면 거기서 멈추거나 방향을 바꾼다.

이 문서가 마일스톤의 단일 출처다. 실험 결과는 `docs/eval_log.md`, 설계는 `docs/design_v0.5.md`, 레인 세팅은
`docs/setup_openbw.md` / `docs/setup_pluto_lane.md`.

## 지금까지 배운 것 (2026-09-29 ~ 10-02, 60게임 이상)

| 조건 (ZvZ 미러, 투혼, 원본 McRave 상대) | 승률 | 결론 |
|---|---|---|
| 베이스라인 (관찰 전용) | 6/11 | 기준선 |
| LLM 전체 레버 | 5/12 | 정적 방어 요청이 드론을 소모 |
| LLM, 정적 방어 끔 | **7/12** | 현재 최선. 베이스라인과 동률 수준 |
| LLM, 자세 끔 | 3/12 | 자세는 유해하지 않음 |
| LLM, 정적 방어 끔 + 경제 레버 | 4/12 | 목표 도달 시 드론 생산 중단이 6분 경제를 깎음 |

- 실시간 레버 개입은 몸체의 일관된 정책을 깎기 쉽다. LLM의 보수적인 요청(성큰, 작은 드론 목표)이 McRave의
  기본 경제 곡선을 침해하는 패턴이 두 번 반복됐다.
- LLM은 전략 지식은 있지만 수치 감각(몇 초 뒤 병력, 지금 싸우면 이기는지)이 약하다. 이 부분은 학습 모델이 세다.
- LLM이 잘하는 곳은 게임 사이다: 로그 읽기, 패인 진단, 상대 모델링, 지식·설정 수정 제안. 그래서 무게중심을
  "실시간 호출을 더 잘하기"에서 "코치가 되어 몸체를 키우기"로 옮긴다.
- 인프라(훅, 상태 요약, 30초 시계열, 1 Hz 유닛 스냅샷, JSONL 로그, eval.compare 게이트)는 그대로 학습 데이터
  파이프라인이 된다.

## 단계

### 0단계. Pluto 레인과 기준 승률 (진행 중)

실제 StarCraft 1.16.1 + BWAPI 4.4.0을 Wine에서 무화면으로 돌려 우리 몸체(McRave, Windows DLL로 교차 빌드)를
Pluto와 붙인다. `docs/setup_pluto_lane.md`.

- 산출물: 투혼 30게임 McRave vs Pluto 승률, Pluto의 게임 기록(`pluto_bandit_*.txt`, 승률 추정 궤적 포함), 리플레이.
- 통과 기준: 없음(측정 단계). 예상 0~10%. 이 숫자가 1단계 목표를 정한다.
- 비용: 컴퓨팅만. 4코어에서 게임당 수 분(Pluto가 추론 속도에 맞춰 스스로 감속).
- 상태: 레인 구축 완료, 첫 게임 실행 중(2026-10-02).

### 1단계. 코치 루프 (현재 자원으로 가능)

LLM이 게임 중에 조종하지 않고, 게임 사이에 로그·리플레이를 읽고 **한 가지** 변경(빌드 선택, 지식 파일, 검증기
규칙, 몸체 설정)을 제안한다. 제안은 12게임 A/B와 `eval.compare` 게이트를 통과한 것만 채택한다(CLAUDE.md 규칙).

- 설계: `docs/design_v0.5.md` §10. 코치 입력 = `eval/results/*/logs` + 스냅샷 + Pluto 기록. 출력 = 변경 1건 + 근거.
- 상대 맞춤 전략은 치트가 아니라 정당한 전략이다(사람 프로도 그렇게 한다). Pluto는 고정 정책이라 약점이 있을
  수 있고, 그걸 찾는 것이 1단계의 핵심이다. 범용성은 2단계 이후 여러 상대로 넓히며 확보한다.
- 통과 기준: 10사이클 안에 Pluto 상대 승률이 0단계의 2배 이상(그리고 McRave 미러에서 regressed가 아닐 것).
  못 넘으면 코치만으로는 부족하다는 결론이고, 2단계 판단으로 넘어간다.
- 기간·비용: 1~2개월, 월 수십만 원(LLM 호출은 게임당이 아니라 사이클당).

### 1.5단계. 데이터와 사전 작업 (현재 자원으로 가능, 2단계와 무관하게 가치 있음)

2단계 착수 여부와 상관없이, 지금 가용 자원으로 뽑아 둘 수 있는 것.

- 게임 데이터 기반 지식 베이스: BWAPI에서 유닛·무기·업그레이드·테크 수치를 자동 추출해 `knowledge/`에 정리
  (LLM의 수치 오류를 줄이는 가장 싼 방법). 빌드 라이브러리(Liquipedia → McRave 빌드명 매핑), 우리 로그에서
  타이밍 통계, 정찰 해석 카드, 투혼 맵 지식 검토(`eval/results/map_dump_fighting_spirit.json` → `knowledge/maps`).
- 학습용 데이터셋 포맷: 1 Hz 스냅샷 + 지시 + 결과를 한 테이블로 (상태, 행동, 보상). 지금 로그를 그대로 변환.
  공개 리플레이(STARDATA 6.5만 판 등)도 같은 포맷으로 파싱할 수 있게 스키마를 고정.
- Pluto 기록 수집: 0·1단계 게임마다 Pluto의 승률 추정 궤적과 선택 빌드를 모아 "어디서 Pluto가 자신을 잃는가"를
  분석(코치 루프의 입력).
- LLM 지식 퀴즈: 전략·수치 질문 세트로 모델의 스타 지식을 측정해 지식 베이스가 메워야 할 구멍을 정한다.
- 30게임 재측정: 베이스라인 vs 정적 방어 끔(M2). 12게임은 구간이 넓다.

### 2단계. 학습 요소 삽입 (자금 여유를 보고 결정, 미정)

빌드 선택 밴딧(Pluto 전용), 교전 판단 모델, 공개 리플레이와 우리 로그로 매크로 정책 모방학습(수천만 파라미터급).
1.5단계의 데이터셋이 입력이고, LLM 코치는 보상·커리큘럼·진단을 맡는다.

- 통과 기준: 학습 정책이 McRave보다 Pluto 상대 승률이 높을 것.
- 기간·비용: 3~6개월, GPU 500만~2천만 원. **할지 말지는 1단계 결과와 자금 여유를 보고 정한다.**

### 3단계. 자기대전 RL (2단계 이후, 미정)

모방학습 초기값에서 Pluto를 리그 상대로 넣고 RL. 사실상 Pluto 재현에 가까운 과제.
6~12개월, 5천만~1억 원 이상. 소규모 연구팀 규모이며 보장 없음. 2단계 결과를 보고 판단.

## 지원 과제 (단계와 병행)

- 검증기 자원 검사, 더 똑똑한 정적 방어 게이트(적 스파이어 확인 시 스포어 1개), 경제 레버 재설계(바닥 의미론
  또는 priority만), 정찰 정책 훅, 리플레이·지시 정렬, 실시간 속도 옵션, 사람 대전용 Windows 레인.
- 대안 무대(참고): 턴제 문명(FreeCiv/CivRealm)은 LLM 판단력 검증에 더 맞는 게임이다. 스타 목표가 막히면 고려.
