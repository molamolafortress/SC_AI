# StarCraft AI Brainstorm Log

## 2024-01-15 Initial Discussion

### Core Architecture Proposal

3개 레이어 구조:
- **전략 (Strategy)** - LLM
- **전술 (Tactics)** - SLM
- **마이크로컨트롤 (Micro)** - 딥러닝/RL

### 왜 이 구조인가?

1. **전략 레이어가 시간이 걸려도 괜찮은 이유:**
   - 큰 틀에서 정의/분석/답 도출
   - 고민을 많이 해야 하는 영역

2. **마이크로 레이어는 이미 해결된 문제:**
   - 최적의 답이 나와있음
   - 기존 모델들 존재

3. **LLM이 전략에 적합한 이유:**
   - 스타크래프트 빌드는 시간 기반 예측 가능
   - "배럭 언제 지었는지", "마린 숫자" → 상대 빌드 방향성 유추
   - 딥러닝은 "본 것만" 판단, LLM은 "안 보이는 것" 추론 가능
   - Fog of War 상황에서 유리

## BWAPI vs 직접 입력

### BWAPI 특징
- 메모리에서 게임 데이터 직접 읽음
- Fog of War 존중 (치트 아님)
- 정확하고 빠름
- 대부분의 SC AI 봇이 사용

### 직접 입력 (화면 인식) 방식
- 화면 캡처 → 이미지 분석
- 마우스/키보드 시뮬레이션
- "진짜 사람처럼" 플레이
- 온라인 래더에서 플레이 가능
- 추가 필요: YOLO object detection, OCR, 마우스 정밀 제어

### 결정: BWAPI로 빠르게 검증 후 진행

## BWAPI가 제공하는 정보

**Fog of War 존중:**
> BWAPI only reveals the visible parts of the game state to AI modules by default.

### 데이터 카테고리
| 카테고리 | 데이터 |
|---------|--------|
| 유닛 기본 | ID, 타입, 소유자, 좌표, 방향, 속도 |
| 상태 | HP, 에너지, 쉴드, 쿨다운 |
| 행동 | 현재 명령, 타겟, 이동 중인지 |
| 건물 | 건설 진행도, 애드온, 생산 큐 |
| 자원 | 미네랄, 가스, 서플라이 |
| 맵 | 지형, 리전, 시야 정보 |

### 이벤트 콜백
```
onUnitCreate()    - 유닛 생성 시
onUnitDestroy()   - 유닛 파괴 시 (보이는 것만)
onUnitMorph()     - 변태 시 (드론→해처리)
onUnitHide()      - 시야에서 사라질 때
onUnitShow()      - 시야에 나타날 때
```

## 하드웨어 요구사항

### 사용 가능 스펙
- GPU: RTX 4090 (24GB VRAM)
- RAM: 64GB
- CPU: Ryzen 7800X

### 레이어별 요구사항
| 레이어 | 모델 예시 | VRAM 요구 | Latency 목표 |
|--------|----------|-----------|-------------|
| 전략 (LLM) | Llama 3 70B Q4, Qwen 72B | 35~40GB (Q4) | 5~30초 OK |
| 전술 (SLM) | Llama 3 8B, Mistral 7B | 6~8GB | 1~3초 |
| 마이크로 (RL) | 작은 Policy Network | 1~2GB | <50ms |

### 추천 구성: 하이브리드
- 전략: Claude API / GPT-5.2 / Gemini 3.0 Pro (빠르고 강력)
- 전술: Gemini Lite / GPT-4o-mini (로컬 또는 API)
- 마이크로: 로컬 RL

### 병목은 VRAM보다 Latency
스타크래프트는 24 FPS (프레임당 ~42ms). 비동기 설계 필수.

```
[LLM 전략] -----(5초마다)-----> 전략 업데이트
     ↓
[SLM 전술] -----(0.5초마다)---> 전술 명령
     ↓
[RL 마이크로] --(매 프레임)---> 유닛 컨트롤
```

## State Manager 역할 논의

### 왜 필요한가?
| 기능 | BWAPI | State Manager 역할 |
|------|-------|-------------------|
| 현재 유닛 정보 | ✓ 제공 | - |
| 시야 밖 적 유닛 추적 | ✗ 사라짐 | "마지막으로 본 위치" 기억 |
| 히스토리 | ✗ 현재만 | "3분 전 적 배럭 2개 봤음" |
| 빌드 추론 | ✗ 없음 | 데이터만 제공 (판단은 LLM) |

### 역할 범위 결정
**Level 1.5: 사실 정리만 (판단 X)**

| 하는 것 | 안 하는 것 |
|--------|-----------|
| 적 유닛/건물 기록 | "이건 X 빌드다" 판단 |
| 타임스탬프 저장 | "위협적이다" 평가 |
| 마지막 위치 기억 | "어디로 갔을 것" 예측 |
| 이벤트 로그 | "그래서 어떻게 해야" 제안 |

## 레이어 간 통신

### JSON 기반 통신 결정
- 구조화된 데이터
- 명확한 스키마
- 로깅/디버깅 용이

### LLM Output에 Reasoning 포함
```json
{
  "decision": {...},
  "reasoning": "적 2배럭 확인, 수비 가능 판단, 경제 우위 가져가기 위해 확장"
}
```

### Reasoning 필드의 가치
| 용도 | 설명 |
|------|------|
| 로깅/디버깅 | 왜 졌는지 나중에 분석 |
| SLM 컨텍스트 | "수비적으로 플레이해" 뉘앙스 전달 |
| 학습 데이터 | 좋은 판단 → fine-tuning 데이터로 |
